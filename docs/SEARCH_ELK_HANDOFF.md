# 검색 데모 구조와 실행 계약

## 데이터 흐름

상품·브랜드·판매 지표는 `fixtures/products.json`, 회원 행동은 `fixtures/events.json`에서 작성한 가상 값입니다. `demo:setup`이 SQLite 원본을 만들고, `demo:seed`가 인덱스 전용 Nori 템플릿·색인 설정·상품·콘텐츠·행동 인덱스를 생성합니다.

`node-cron → 분리 워커 → SQLite SELECT 행 스트리밍 → Elasticsearch Bulk → 선택적 임베딩 → 별칭 전환` 순서입니다. 관리자에서 등록하는 SQL은 로컬 DB를 대상으로 실행합니다. 환경별 DB 자격증명이나 별도 회원 시스템은 사용하지 않습니다.

## 색인

- 전체색인은 `<별칭>-yyyyMMddHHmm` 인덱스를 만듭니다. 최종 refresh·문서 수·검색 검증 후 별칭을 원자적으로 전환합니다. 상품 0건 또는 기존 대비 50% 미만이면 기존 별칭을 유지합니다.
- 추가색인은 `DEMO_SYNC_QUEUE`를 SQLite 트랜잭션으로 선점하고 추가·갱신 후 삭제합니다. 모두 성공해야 `COMPLETE`가 됩니다. 실패 시 재시도 횟수를 늘리고 한도에 도달하면 `FAILED`가 됩니다.
- 작업 이력·중복 실행 방지·하트비트·취소 상태는 `.commerce-indexing-jobs-v1`에 저장합니다. 취소는 진행 중인 처리 묶음 사이에서 검사하며 이미 반영한 Bulk 결과는 되돌리지 않습니다. SQLite 단일 SQL 실행은 동기식이므로 장시간 SQL을 즉시 중단하는 기능은 제공하지 않습니다.
- 예약 작업은 최초 설정에서 꺼져 있습니다. PM2 사용 시 0번 인스턴스만 스케줄을 등록합니다.
- `dev`와 `prd`는 같은 가상 원본을 사용하고 색인·검색 설정을 분리합니다. 상품 변경 큐는 공통이므로 각 환경 검증 전에 `demo:changes`를 실행합니다.

## 검색

Nori 분석, 단어 정책, 구조화 필터, 필드 가중치, 인기도, 비즈니스 룰, 카테고리 보정과 개인화를 조합합니다. 선택적 혼합 검색은 실제 384차원 임베딩과 RRF를 사용합니다. 기본 설정에서는 임베딩과 AI 확장을 사용하지 않습니다.

검색 비교 기준은 같은 가상 인덱스에 대한 기본 `multi_match`입니다. 상품·콘텐츠 이미지는 `public/demo/product.svg`를 사용합니다. 운영 성능 수치나 실제 고객 행동은 포함하지 않습니다.
