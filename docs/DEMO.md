# 가상 상품 실행과 검증

## 준비

Node.js 24 이상과 Docker Compose를 설치한 뒤 저장소 루트에서 `npm ci`, `npm run demo:setup`, `docker compose up -d --build --wait`, `npm run demo:seed`, `npm run dev`를 순서대로 실행합니다.

`/login`에서 `.env.local`의 비밀번호로 로그인합니다. 최초 상품은 환경별 24개, 콘텐츠는 환경별 3개입니다. 기존 관리자 설정을 바꾼 뒤 `demo:seed`를 재실행해도 설정과 이미 존재하는 별칭을 덮어쓰지 않습니다.

## 확인 순서

1. 대시보드에서 상품·콘텐츠 인덱스와 문서 수를 확인합니다.
2. 검색 시뮬레이터에서 `모던리프 재킷`, `여름 원피스`, `10만원 이하 재킷`을 검색합니다.
3. 검색 비교에서 기본 키워드 검색과 가중치·정책을 적용한 결과를 비교합니다. 비교 기준은 같은 로컬 인덱스이며 외부 검색 서비스가 아닙니다.
4. 비즈니스 룰에서 가상 브랜드 `모던리프`의 점수를 조정하고 시뮬레이터의 적용 근거를 확인합니다.
5. `npm run demo:changes` 후 개발 상품 추가색인을 실행합니다. `DEMO0001.sale_amt=88000`, `DEMO0002` 삭제, 큐 완료 상태를 확인합니다. 운영 데모도 확인하려면 변경 예제 생성 명령을 다시 실행한 뒤 운영 상품 추가색인을 실행합니다.
6. 전체색인은 새로운 날짜 인덱스의 문서 수와 검색을 검증한 뒤 별칭을 바꿉니다. 날짜 접미사는 분 단위이므로 같은 환경의 전체색인은 1분 이상 간격으로 실행합니다.
7. 개인화를 켜고 시뮬레이터에서 가상 회원 `1001`과 `1002`의 결과를 비교합니다. 두 회원의 행동 데이터는 `fixtures/events.json`에 있습니다.

## 데이터와 중지

`fixtures/products.json`이 최초 원본입니다. SQLite DB는 `.demo/catalog.sqlite`, 인덱스는 Docker 전용 볼륨에 저장됩니다. 설정 저장소는 `.commerce-` 접두어를 사용합니다. SQLite 조회 연결은 읽기 전용이며 큐와 변경 예제 명령만 쓰기 연결을 엽니다.

`docker compose stop`으로 Elasticsearch를 중지합니다. API는 실행한 터미널에서 종료합니다. 환경 파일과 로컬 DB는 Git에 포함하지 않습니다.

## 검증 범위

`npm run test:demo`는 실제 임시 SQLite DB로 원본 읽기, 변경 큐 선점·실패 재시도·완료, GEO 속성 읽기와 색인 변환을 검증합니다. 실제 Elasticsearch 실행은 `demo:seed`와 API 검색으로 별도 확인합니다. 테스트 대역의 결과를 Elasticsearch 통합 검증으로 간주하지 않습니다.

`npm run test:integration`은 API와 전용 Elasticsearch가 실행 중일 때 사용합니다. 로그인·상품/콘텐츠/기획전 검색·개인화·실제 추가색인 워커·전체색인 별칭 전환을 검증합니다. 가상 상품 변경 후 초기 상품 24개와 가격을 복원하므로 관리자에서 다른 색인을 실행하지 않는 상태에서 수행합니다.
